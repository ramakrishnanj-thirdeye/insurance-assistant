# 10 – UI (Streamlit)

Milestone: M8 (thin chat page in M4) · Depends on: 09

## Goal
A glass-box demo UI: every answer shows how it was produced, and the dossier, coverage matrix, leakage
radar and eval dashboard make the system's strengths visible in a 12-minute client demo.

## Layout
`ui/app.py` (multipage, `st.navigation` with callable pages: `chat_page.py`, `dossier_page.py`, `eval_page.py`; pure helpers in `views.py`, `trace_view.py`, `dossier_view.py`, `eval_view.py`). Pages per persona (`views.page_keys`): Chat for everyone, Claim Dossier for claims_agent and supervisor, Eval Dashboard for `can_read_eval_reports`. All data comes from the API (spec 09), never from DuckDB directly.

Sidebar (every page): persona selector; for customer persona a principal picker (10 sample customers with
open claims, including CUST139920 who owns CLM300210); badges for LLM profile, as-of date (2026-10-01) and
coverage-matrix status; a **Conversations** list and a "New conversation" button.

Conversations list (from `GET /threads`, for the current persona and principal): title, relative time, and a
"review pending" badge for awaiting_review threads. Clicking one loads `GET /threads/{id}` and re-renders its
messages and last trace; a small menu offers rename and delete. The open thread ID is kept in the URL
(`st.query_params["thread"]`), so a browser refresh reopens the same conversation. Changing persona or
principal starts a new conversation and reloads the list for that identity. Opening an awaiting_review
thread shows the review card straight away.

| Page | Content |
| --- | --- |
| Chat | Streaming chat. Each assistant message: answer with citation chips (click → expander with the clause text); a **Trace** panel (st.expander or right column): intents, tools with timings, SQL in a code block, retrieved chunks table (label, fused rank, rerank score, via), rule results table, verifier checks V1–V7, LLM calls with tokens and latency, prompt versions. ## Behaviour
- Streaming via `httpx` SSE client. The draft streams in a muted style (`st.caption`) with a "checking…"
  badge, then shows in the normal style with "✓ verified" when `final.verified` is true. After a verify
  retry the draft is cleared, the badge reads "revising…" and the new attempt streams; on the final
  fallback the fallback answer is shown without the badge. `draft_hidden` clears the draft and leaves only
  "checking…" until `final`. The fold is `TurnView` in `api/client.py` (pure, unit-tested).
- **Status line** above the answer area, from `config/ui_status.yaml`: per node a list of phrases (the
  first at node start, rotating on each `heartbeat`), per tool a specific line ("Pulling up claim
  CLM300210", "Searching the Health Secure Plus wording", "Checking the claim's documents"), and after the
  planner "Understood: policy question · Health Secure Plus". Every phrase describes what is actually
  happening. Placeholders are limited to claim_id, policy_id, hospital_id and product (plus intents), and
  values are re-checked with `status_args`, so customer names never appear. A sidebar "Status tone"
  (professional | playful) picks the phrase set; the customer persona always gets professional.
- Citation chips are compact (`HSP §5`) with the full label in the tooltip.
- Severity colours: blocker red, warning amber, escalate purple, info grey, pass green (Streamlit theme colours, consistent everywhere).
- No browser storage; session_state only.

## Demo check
`make demo-check` (`insurai.eval.demo_check`) runs the docs/DEMO.md run-of-show headlessly against the running
API through `ApiClient`, one fresh thread per step (source `demo`, deleted afterwards), and reports pass or fail,
the reason and the seconds per step (`--json` for the timings, `--only S01,S05`). Steps S01–S15: greeting
(template, no LLM), own claim status (cites the claim), another customer's claim (access refusal), guarantee
question on CLM311320 (mandated wording, §15, the claim's needs, no promise), maternity waiting period (tokens
streamed, Health Secure Plus citation), drunk driving under Motor Protect Comprehensive (§ citation,
intoxication), "Analyze claim CLM300210" (interrupt with blockers, approve with a note, decision in the answer),
"Why is CLM300210 pending?" (Approved), summary of CLM300423 (no pause), vet bills for a pet dog (abstention
template, not model-written), approval rate by line of business (chart spec), paid in full despite a co-pay
(20,903), the dossier for CLM300210 (4 missing documents) and the eval reports (a scored calibration and an
ablation run), and the maternity question asked as the customer CUST139920 (S15: cited, and the returned
trace renders through the Chat page's "How this answer was produced" panel in Streamlit AppTest without an
exception).

`make demo` (`insurai.demo`) warms the Ollama models of the active profile with `keep_alive`, starts the API
without `--reload`, waits for /health, then starts the UI; it refuses to start when something already answers on
the API port.
